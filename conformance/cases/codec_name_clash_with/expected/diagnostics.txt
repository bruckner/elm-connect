naming::codec_collision

  × The package `shelf.v1` has two definitions whose codecs both become the
  │ Elm value `decodeBoxWith`.
    ╭─[shelf.proto:11:9]
 10 │
 11 │ message Box {
    ·         ─┬─
    ·          ╰── the JSON decoder of message `shelf.v1.Box` taking the registry becomes `decodeBoxWith`
 12 │   google.protobuf.Any content = 1;
 13 │ }
 14 │
 15 │ message BoxWith {
    ·         ───┬───
    ·            ╰── and so does the JSON decoder of message `shelf.v1.BoxWith`
 16 │   string label = 1;
    ╰────
  help: The JSON decoder of a message or oneof that holds a
        `google.protobuf.Any`, directly or through its fields, takes the
        registry and is named with `With` at the end (`decodeNoteWith`), so
        the JSON decoder of a type named for it with `With` at the end
        (`NoteWith` beside `Note`) takes the same name, and a module cannot
        define two values with one name. Rename one of them in the proto, or
        rename one with `rename=shelf.v1.BoxWith:<Elm name>`.
