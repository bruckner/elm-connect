options::invalid_rename

  × The rename of `settings.v1.SettingsService.Version` gives
  │ `elmConnectVersion_`, which a method cannot be named.
    ╭─[settings.proto:21:7]
 20 │   // rename cannot end in `_`.
 21 │   rpc Version(Settings) returns (Settings);
    ·       ───┬───
    ·          ╰── a method here
 22 │   // `descriptorDefaultSettings` is the descriptor of `DefaultSettings`.
    ╰────
  help: `settings.v1.SettingsService.Version` is a method, which becomes an
        Elm value, and a rename's name is used as it is, so it must be an
        ASCII lowercase letter followed by letters, digits or underscores, not
        ending in an underscore, and not an Elm reserved word.

naming::value_collision

  × The service `settings.v1.SettingsService` has two methods that both become
  │ the Elm value `getSettings`.
    ╭─[settings.proto:13:7]
 12 │   rpc DefaultSettings(Settings) returns (Settings);
 13 │   rpc GetSettings(Settings) returns (Settings);
    ·       ─────┬─────
    ·            ╰── method `settings.v1.SettingsService.GetSettings` becomes `getSettings`
 14 │   // `Get_Settings` is `getSettings` too.
 15 │   rpc Get_Settings(Settings) returns (Settings);
    ·       ──────┬─────
    ·             ╰── and so does method `settings.v1.SettingsService.Get_Settings`
 16 │   // `elmConnectVersion` is fine: the value every generated module
    ╰────
  help: A service's module defines one value per method, its name with its
        leading capitals lowercased and underscores dropped, so names that
        differ only in those ways end up the same, and a module cannot define
        two values with one name. Rename one of the methods in the proto, or
        rename one with `rename=settings.v1.SettingsService.Get_Settings:<Elm
        name>`.

naming::value_collision

  × The service `settings.v1.SettingsService` has a method that becomes the
  │ Elm value `descriptorDefaultSettings`, which is another method's
  │ descriptor.
    ╭─[settings.proto:12:7]
 11 │   // default lives in the package's module, the method in the service's.
 12 │   rpc DefaultSettings(Settings) returns (Settings);
    ·       ───────┬───────
    ·              ╰── the descriptor of method `settings.v1.SettingsService.DefaultSettings` becomes `descriptorDefaultSettings`
 13 │   rpc GetSettings(Settings) returns (Settings);
 14 │   // `Get_Settings` is `getSettings` too.
 15 │   rpc Get_Settings(Settings) returns (Settings);
 16 │   // `elmConnectVersion` is fine: the value every generated module
 17 │   // defines is `elmConnectVersion_`, which no method name derives to.
 18 │   rpc ElmConnectVersion(Settings) returns (Settings);
 19 │   // Nor can a rename give a method that name (options.txt): a value's
 20 │   // rename cannot end in `_`.
 21 │   rpc Version(Settings) returns (Settings);
 22 │   // `descriptorDefaultSettings` is the descriptor of `DefaultSettings`.
 23 │   rpc DescriptorDefaultSettings(Settings) returns (Settings);
    ·       ────────────┬────────────
    ·                   ╰── and so does method `settings.v1.SettingsService.DescriptorDefaultSettings`
 24 │ }
    ╰────
  help: A service's module defines two values per method: its call, its name
        with its leading capitals lowercased and underscores dropped, and its
        descriptor, `descriptor` followed by the call's name with the first
        letter uppercased. So a method named for another's descriptor
        (`DescriptorGetNote` beside `GetNote`) takes that descriptor's name,
        and a module cannot define two values with one name. Rename one of the
        methods in the proto, or rename one with
        `rename=settings.v1.SettingsService.DescriptorDefaultSettings:<Elm
        name>`.
