naming::codec_collision

  × The package `shelf.v1` has two definitions whose codecs both become the
  │ Elm values `encodeBookBytes` and `decodeBookBytes`.
    ╭─[shelf.proto:12:9]
 11 │
 12 │ message Book {
    ·         ──┬─
    ·           ╰── the binary codecs of message `shelf.v1.Book` become `encodeBookBytes` and `decodeBookBytes`
 13 │   string title = 1;
 14 │ }
 15 │
 16 │ message BookBytes {
    ·         ────┬────
    ·             ╰── and so do the JSON codecs of message `shelf.v1.BookBytes`
 17 │   bytes content = 1;
    ╰────
  help: A type's protobuf binary codecs are named for its JSON codecs with
        `Bytes` at the end (`encodeNoteBytes` beside `encodeNote`), so the
        JSON codecs of a type named for another with `Bytes` at the end
        (`NoteBytes` beside `Note`) take the same names, and a module cannot
        define two values with one name. Every type has both codecs, whatever
        the `wire` option says. Rename one of them in the proto, or rename one
        with `rename=shelf.v1.BookBytes:<Elm name>`.
