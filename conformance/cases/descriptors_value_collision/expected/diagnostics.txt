naming::value_collision

  × The descriptor module of `profile.v1.Profile` would define the Elm value
  │ `nickname` twice.
    ╭─[profile.proto:8:10]
  7 │   // descriptor is called too.
  8 │   string display_name = 1;
    ·          ──────┬─────
    ·                ╰── field `display_name` becomes `nickname`
  9 │   oneof alias {
 10 │     string nickname = 2;
    ·            ────┬───
    ·                ╰── and so does oneof field `nickname`
 11 │   }
    ╰────
  help: A message's descriptor module (`Notes.V1.Note` for `notes.v1.Note`)
        defines `descriptor`, the message's descriptor, and one value per
        field, named as its record field is (a oneof member as a field would
        be; a field named `descriptor` takes `descriptor_`), so two fields
        whose values meet cannot both be defined. Rename the field in the
        proto, or rename it with `rename=<proto full name>:<Elm name>`.

naming::value_collision

  × The field `version` is renamed to the Elm value `elmConnectVersion_`,
  │ which every generated module defines already.
    ╭─[profile.proto:13:10]
 12 │   // Renamed to the value every generated module defines (options.txt).
 13 │   string version = 3;
    ·          ───┬───
    ·             ╰── field `version` is renamed to `elmConnectVersion_`
 14 │ }
    ╰────
  help: Every generated module defines `elmConnectVersion_`, which names the
        release of the generator it came from, so no method or field can take
        that name in the module that defines it. Give it another name in its
        `rename=<proto full name>:<Elm name>`.
