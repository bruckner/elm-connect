options::invalid_rename

  × The rename of `profile.v1.Profile.version` gives `elmConnectVersion_`,
  │ which a field cannot be named.
    ╭─[profile.proto:14:10]
 13 │   // which a field's rename cannot take, ending in `_`.
 14 │   string version = 3;
    ·          ───┬───
    ·             ╰── a field here
 15 │ }
    ╰────
  help: `profile.v1.Profile.version` is a field, which becomes an Elm record
        field, and a rename's name is used as it is, so it must be an ASCII
        lowercase letter followed by letters, digits or underscores, not
        ending in an underscore, and not an Elm reserved word.

naming::value_collision

  × The descriptor module of `profile.v1.Profile` would define the Elm value
  │ `nickname` twice.
    ╭─[profile.proto:8:10]
  7 │   // descriptor is called too.
  8 │   string display_name = 1;
    ·          ──────┬─────
    ·                ╰── field `display_name` is renamed to `nickname` by `rename`
  9 │   oneof alias {
 10 │     string nickname = 2;
    ·            ────┬───
    ·                ╰── and so does oneof field `nickname`
 11 │   }
    ╰────
  help: A message's descriptor module (`Notes.V1.Note` for `notes.v1.Note`)
        defines `descriptor`, the message's descriptor, and one value per
        field, named as its record field is (a oneof member's for the end of
        its constructor; a field named `descriptor` takes `descriptor_`), so
        two fields whose values meet cannot both be defined. That name comes
        from `rename=profile.v1.Profile.display_name:nickname`: give it
        another there, or rename the other one in the proto.
