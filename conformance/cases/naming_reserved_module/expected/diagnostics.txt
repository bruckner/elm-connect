naming::reserved_module

  × The package `devices.aux` becomes the Elm module `Devices.Aux`, and `Aux`
  │ is a reserved file name on Windows.
   ╭─[devices.proto:5:1]
 4 │ // Windows, in any case.
 5 │ package devices.aux;
   · ──────────┬─────────
   ·           ╰── package `devices.aux` becomes `Devices.Aux`
 6 │
   ╰────
  help: Each module is written to a file named for it (`Notes.V1.Note` to
        `Notes/V1/Note.elm`), and Windows reserves `CON`, `PRN`, `AUX`, `NUL`,
        `COM1` to `COM9` and `LPT1` to `LPT9` as file names in any case and
        with any extension, so `Aux.elm` or a directory `Aux` cannot be
        created there and git refuses to check it out. It is refused on every
        OS so that generated code can be checked out anywhere. Rename it with
        `rename=devices.aux:<Elm name>`.

  × The package `json.decode` becomes the Elm module `Json.Decode`, which is a
  │ module of elm/json.
   ╭─[json/decode.proto:4:1]

   · ──────────┬─────────
   ·           ╰── package `json.decode` becomes `Json.Decode`

   ╰────
  help: An application that depends on elm/json cannot define a module of the
        same name: every `import Json.Decode`, in the generated code or the
        application's, becomes ambiguous. Move the module with
        `rename=json.decode:<Elm name>` or `module_prefix=<Elm module>`.
