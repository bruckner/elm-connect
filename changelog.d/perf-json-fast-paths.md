- Encoding a message as JSON is faster: by 30 % for a single message
  and half for a list of 300, in the package's benchmark, and with it
  building a Connect POST (30 %) and a transcoded request with a body
  (7 to 16 %).
- Building a Connect GET request takes half the time, and a transcoded
  request with path or query values 6 to 12 % less.
- Reading a JSON answer is faster: by about a quarter for a small
  answer, a fifth for a 1 KB one, 27 to 29 % for a list of 300 messages
  and 15 % for an error with two typed details; a JSON `bytes` field is
  checked about three times as fast.
- Code generated by this release decodes each message with the new
  `Proto.Json.message`, which checks once that the JSON is an object,
  and its fields with `messageField`, `messageFieldEither`,
  `messageValueField` and `messageValueFieldEither`, which do not check
  it again. Decoders written with `field` and its siblings work as
  before.
