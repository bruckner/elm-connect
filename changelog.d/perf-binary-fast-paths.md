- Reading protobuf binary is faster: by 39 % for a single message, half
  for a list of 300, 27 to 46 % for nested, map-heavy and 16-field
  messages in the package's benchmark, and 30 % for a 1 KB answer over
  Connect's proto codec (27 to 28 % over gRPC-Web). Unpacking an `Any`
  takes about a quarter less time, and so does writing one as JSON.
- Writing protobuf binary is faster: by 17 % for a single message, 12 %
  for a list of 300, 30 to 57 % for wide, nested and packed `int32`
  fields, and 21 to 22 % for building a binary request. A packed run of
  doubles is written about 17 % slower. The bytes written are the same.
- `Proto.Any.pack` of a message that cannot hold an `Any` (one built by
  `Proto.Message.init`, as generated code builds every such message) no
  longer encodes the message as JSON first; it writes the binary
  straight away, with the same result.
- Code generated by this release sets a field in a binary merge step
  by writing the record out whole, for a message of up to 64 fields,
  where it used a record update; such messages decode five to seven
  times faster field by field, and the generated module is larger (a
  64-field message's merge is about 0.8 KB gzipped more). Generated
  code from earlier releases works as before.
