- A `double` field written as a JSON number past a double's range (such
  as `1e999`, which JavaScript's JSON parser reads as an infinity) fails
  to decode, and a `float` field (and `Proto.WellKnown.floatValue`)
  fails on a value whose magnitude is past the largest `float`,
  3.4028234663852886e38. Both were read as given
  before; the strings `"Infinity"`, `"-Infinity"` and `"NaN"` still
  decode. Code generated by this release decodes `float` fields with the
  new `Proto.Json.float32`.
- `Proto.Timestamp.fromString`, and so every `Timestamp` field, refuses
  a lowercase `t` or `z` (`1970-01-01t00:00:00z`): RFC 3339 allows
  them, proto3 JSON does not. They were accepted before.
- An `Any` whose `"@type"` is not a type URL (empty, without a `/`, or
  with nothing after the last `/`) fails to decode; it was read as an
  `Any` of that text before. A well-formed URL of a type the client does
  not know still decodes.
