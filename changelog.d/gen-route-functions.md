- Transcoded requests are built by generated route functions, one per
  HTTP binding (`routeGetNote0 : GetNoteRequest -> Proto.Route.Route`),
  that read the typed request instead of encoding it to JSON and reading
  each field back: building one takes about 40 % less time, and the
  notes example's bundle is 3.5 % smaller gzipped (5.6 % for a program
  of many bindings), since a program that names no binding data carries
  neither it nor the interpreter that read it. The requests are the
  same, byte for byte.
- A request message whose bindings put fields in the query gets a query
  encoder in its package's module, `queryOfListNotesRequest`, which its
  route functions share. A method named for a route function
  (`RouteGetNote0` beside `GetNote`) is `naming::value_collision`. Under
  `codec=proto` a method gets no routes, since transcoding takes JSON.
- New modules `Proto.Route` (the route record and the path and body
  helpers route functions call) and `Proto.Query` (the query helpers).
- `Proto.Method.json`, `proto` and `both` take the service's full name
  and the method's name (`"notes.v1.NotesService" "GetNote"`) in place
  of a descriptor, and `Proto.Method.withIdempotency`,
  `Proto.Method.withRoutes` and `Proto.Method.withBindings` set the rest;
  `Proto.Method.toDescriptor` is gone. A method written by hand gives
  its `Proto.Http` bindings to `withBindings`. The generated
  `descriptorGetNote` keeps its form, and is no longer held by the call:
  a program that does not name it drops it.
- `Rpc.Call.descriptor` is gone: name `descriptorGetNote` instead.
  `Rpc.Call.procedure` and `Rpc.Trace.procedure` give the Connect path,
  `/notes.v1.NotesService/GetNote`, and `Rpc.Call.toJson` and
  `Rpc.Trace.toJson` gain a `procedure` key beside `service` and
  `method`.
- A protobuf binary answer that does not decode names the method's
  procedure (`the body is not the response of notes.v1.NotesService/GetNote
  in protobuf binary`) rather than the response type.
- Generated code names `Proto.Version.v0_2`, and the runtime exposes it
  alone: code generated by 0.1 fails to compile on `v0_1` and must be
  regenerated.
